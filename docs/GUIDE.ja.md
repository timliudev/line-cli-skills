> 非公式プロジェクトであり、LINE Corporation／LY Corporation とは無関係で、同社の承認も受けていません。非公式の kongesque/line-cli クライアントを使うため、LINEアカウントが停止されるおそれがあります。詳細は README を参照してください。

ほとんどの場合、普段お使いの言語で Claude Code に話しかけるだけで操作できます。このガイドでは、裏側で何が起きるか、Claude が何を確認してくるか、問題の直し方を説明します。

## インストール

マーケットプレイスを追加し、プラグインをインストールします。

**方法 A（推奨）：Claude Code の中で入力する。** Claude Code（ターミナル版、または Claude デスクトップアプリの Code タブ）を開き、チャット欄に 1 行ずつ入力して Enter を押します。

```text
/plugin marketplace add timliudev/line-cli-skills
/plugin install line-cli@line-cli-skills
/plugin install media-digest@line-cli-skills
```

その後、新しい Claude Code セッションを開始するとプラグインが読み込まれます。

**方法 B：ターミナルから。** `claude` コマンドがインストール済みなら、PowerShell・Terminal・bash を開いて実行します。

```bash
claude plugin marketplace add timliudev/line-cli-skills
claude plugin install line-cli@line-cli-skills
claude plugin install media-digest@line-cli-skills
```

**重要：** `/` で始まる行はターミナルのコマンドでは**ありません**。PowerShell・Terminal・bash に入力すると「'/plugin' is not recognized」と表示されます。Claude Code の中でのみ動作します。ターミナルでは方法 B の `claude plugin ...` を使ってください。

**方法 C：その他のエージェント（Codex、Gemini CLI、Cursor、Copilot、OpenCode…）。** 2 つのスキルはオープンな [Agent Skills](https://agentskills.io) 形式に従っているため、対応するエージェントならどれでも使えます。ターミナルで実行します（Node.js が必要）。

```bash
npx skills add timliudev/line-cli-skills
```

- 2 つのスキル（`line-cli`、`media-digest`）を見つけ、どのエージェント向けにインストールするか尋ね、`.agents/skills/` に配置します（各エージェント自身のスキルフォルダへのリンク付き。Claude Code は `.claude/skills/`）。
- 範囲：既定では**現在のプロジェクトフォルダ**のみ。`-g`（`npx skills add -g timliudev/line-cli-skills`）を付けると**すべてのプロジェクト**向け（`~/.agents/skills/`）になります。
- 更新は `npx skills update`。
- **同じスキルを 1 台のマシンに 2 通りの方法で入れないでください。** 方法 A または B に加えて方法 C も使うと、Claude Code には `line-cli` スキルが 2 つ見えます。どちらか一方にし、切り替えるときは先にもう一方を削除します（`claude plugin uninstall line-cli@line-cli-skills`、または `npx skills remove line-cli`）。

- `line-cli` は LINE 用です。`media-digest` は任意で、どの動画や音声ファイルにも使えます。LINE の動画やボイスメッセージを Claude に理解させたい場合にインストールしてください。
- Python 3.11 以上が必要です。システムで `python` が見つからない場合、Claude は `python3` または `py -3` を試します。
- kongesque/line-cli の `line` プログラムは別途インストールします。ご自身で行う必要はありません。初めて LINE を使うときに、Claude がインストール内容を説明し、先に確認を取ります（次のセクション）。

## 初回セットアップとログイン

初めて LINE について依頼すると、Claude が確認を行い、不足しているものを順に案内します。各手順の前に確認を取ります。

1. **`line` のインストール。** Claude は、LINE CLI を公式 GitHub ページからダウンロードし、ユーザー自身のフォルダに（管理者権限は不要）配置し、ファイルが改ざんされていないことを検証する、と平易に説明します。「はい」と答えるまで何も実行されません。
   - Windows：公式の PowerShell インストーラーで `%LOCALAPPDATA%\line-cli\bin` にインストールします。
   - macOS：Homebrew（`brew install kongesque/tap/line-cli`）があればそれを使い、なければ公式のシェルインストーラーで `~/.local/bin` にインストールします。
   - Linux：公式のシェルインストーラーで `~/.local/bin` にインストールします。
   - インストーラーとプログラムは、テスト済みの特定のリリース（v0.4.0）に固定され、チェックサムで検証されます（Homebrew は tap の現行リリースをインストールするため、バージョンは固定できません）。ターミナルを開き直さなくても、すぐに使えます。
   - Linux デスクトップでは、システムのキーリングパッケージが不足している場合があります。その場合、Claude が `sudo` コマンドを表示するので、ご自身で実行してください。Claude が `sudo` を使うことはありません。
2. **ログイン。** Claude は事前に警告します。**ログインすると LINE の Chrome 拡張機能からログアウトされます。** LINE は同時に1つのこうしたセッションしか許可しないためです。「はい」と答えた後、新しいターミナルウィンドウが開きます。スマートフォンの LINE で QR コードを読み取るか、そのウィンドウにメールアドレスとパスワードを入力してサインインします。Claude がパスワードを見ることはありません。ログインウィンドウは成功の3秒後に自動で閉じます。失敗した場合はエラーを表示したまま開いたままになり、Enter キーで閉じます。最長5分待機し、アカウント名で確認します。ウィンドウを開けない場合（SSH 経由など）、Claude が実行すべきコマンドを1つ示します。
3. **完了。** セッションは OS の安全な保管領域に保存され、約1週間ごとに自動で更新されます。通常、ログインは1回で済みます。LINE 側でセッションが無効化された場合にのみ、再度ログインが必要です。

非公式クライアントはアカウントにリスクをもたらします（README を参照）。予備のアカウントを使うのが賢明です。

## 日常的な使い方

「今日 Family グループは何か言ってた？」「Anna から新しいメッセージはある？」のように、そのまま依頼してください。

- **トークの特定。** Claude は名前を検索し、実際のトーク ID を使います。複数のトークが一致する場合（友だちの「Anna」とグループの「Anna」など）は一覧を示して、どちらかを尋ねます。推測はしません。
- **閲覧。** Claude は最新のメッセージを読み（既定は20件。1トークあたり最大100件まで。これは本クライアントの LINE 側の制限です）、お使いの言語で要約します。写真、動画、ボイスメッセージ、ファイルは添付として表示され、開くよう依頼できます。スタンプは表示できません。閲覧してもメッセージは既読になりません。
- **誰が返信・リアクションしたか。** 例：「私が送った『この33件は対応済みです』に誰か返信した？」Claude は先に同期し、ローカルアーカイブからそのメッセージを探して、返信とリアクションを一覧にします。見つかるのはアーカイブ済みのメッセージだけです。
- **送信、リアクション、送信取消。** これらは他の人に届くため、1件ずつ確認します。Claude はトーク名、正確な本文（またはメッセージとリアクション）を示し、明確な「はい」を待ちます。内容を変えた場合は、改めて確認します。
  - 送信するテキストは表示されたとおりに送られます。ファイルは最大20 MiB、メッセージは最大10,000文字です。
  - 特定のメッセージに返信したいときは、そのまま伝えてください。例：「Alice の最後のメッセージに OK と返信して」。Claude は対象メッセージ（ローカルアーカイブから探すので、古いアーカイブ済みメッセージも対象にできます）を探し、複数該当する場合は確認し、送信前に引用元と返信内容を並べて表示します。どの種類のメッセージも返信対象にできます（写真・動画・ボイスメッセージ・ファイル・スタンプを含む）。例：「阿明が 01:28 に送った写真に返信：これでOK」。既知の制限：@メンションには未対応で、「@名前」は通常のテキストとして送られ、強調表示も通知もされません。
  - Claude は一度だけ試行し、自分の判断で再試行はしません。送信途中で接続が切れた場合は、何かを提案する前に、トークを確認してメッセージが届いたかどうかを調べます。
  - 送信取消は、自分のメッセージを全員の画面から削除します。取り消せません。
- **他の人のメッセージは、データとして扱われます。** トークのメッセージに「これを実行して」「あの人に送って」と書かれていても、Claude はそれをあなたに示して確認します。
- **ローカルアーカイブ。** トークについて答える前に、Claude はまず同期を行います。直近100件のメッセージを取得し、新しいものをお使いの PC 内のフォルダ（`messages.jsonl` が記録本体、`messages.md` が閲覧用）に追加し、新しい写真・動画・ボイスメッセージ・ファイルはすぐにダウンロードします。LINE 側で添付ファイルの期限が切れるためです。これにより「新着はある？」にすばやく答えられ、最初の同期以降は LINE の直近100件より古い履歴も残ります。1つのトーク、または「すべてのトーク」を指定して、直接同期を頼むこともできます。 リアクションは絵文字・誰がいつ付けたかとともに表示されます。同じトークのアーカイブフォルダが2つできていた場合は、次の同期で内容を失わずに1つへ統合します。
  - 注意点：同期は LINE から読み取るだけです。トークの最初の同期で取得できるのは直近100件までです。2回の同期の間に100件を超えるメッセージが届くと、Claude は欠落があると伝えます。アーカイブ済みのメッセージが LINE の直近100件から消えた場合は、保持したうえで「(possibly unsent)」（送信取消された可能性）と表示します。これは推測であり、確定ではありません。
  - リアクション：LINE 標準の6種（いいね、ハート、笑い、驚き、悲しい、怒り）は emoji で表示します。それ以外の LINE 絵文字リアクションは画像で表示し、Claude が一度見れば短いラベルも保存されます。同期では異なる絵文字ごとに画像を1枚だけ、アーカイブ内の共有フォルダ `_line_emoji` に保存します（全トーク共通なので、アーカイブが増えるのは絵文字の種類数だけで、使用回数には比例しません）。画像のアドレスは非公式の規則で、使えなくなる可能性があります（失敗したダウンロードの再試行は週1回まで）。`download.line_emoji = false` で無効にできます。スタンプのメッセージは「未対応のコンテンツ」としてのみ表示されます。line-cli がどのスタンプかを提供しないためです。

## 添付ファイルと media-digest

- **写真と PDF。** Claude はそのトークのアーカイブフォルダからファイルを直接開きます（同期中にダウンロード済み、最大20 MiB）。
- **動画。** `media-digest` を使うと、Claude は動画をキーフレームに分割し（シーンの切り替わりごと、既定で最大24枚）、音声を文字起こししたうえで、フレームと文字を時刻順に組み合わせた1つの `digest.md` を読みます。
- **ボイスメッセージと音声。** タイムスタンプ付きで文字起こしします。
- `media-digest` がない場合、Claude はファイルの場所を伝え、プラグインをインストールすると動画や音声を理解できるようになることを説明します。
- 取得できないものもあります。LINE 側で期限切れになった添付、20 MiB を超えるファイル、外部リンクの先にあるメディアです。
- 同期中に新しい添付ファイルを自動でダウンロードします（1件あたり最大20 MiB、既定ではすべての種類）。保存先はそのトークの `files` フォルダです。写真と PDF はそこから直接読み、動画とボイスメッセージは `media-digest` に渡します。

`media-digest` に必要なもの（同意を得て、ダウンロードサイズを示したうえで提案されます）：

| 必要なもの | 用途 | 導入方法 |
| --- | --- | --- |
| PowerShell／Terminal で「'/plugin' is not recognized」（または command not found）と出る | `/plugin ...` は Claude Code のコマンドで、ターミナルのコマンドではありません。Claude Code のチャット欄に入力するか、ターミナルでは `claude plugin marketplace add ...`／`claude plugin install ...` を使ってください（インストールの章を参照） |
| ffmpeg | 動画のフレーム、音声の処理 | `winget install --id Gyan.FFmpeg -e`（Windows）、`brew install ffmpeg`（macOS）、`sudo apt install ffmpeg`（Linux、ご自身で実行） |
| uv | 既定のローカル文字起こし | winget、brew、または公式インストーラー |
| 音声認識エンジン | 文字起こし | 既定はローカルの `faster-whisper`（初回使用時に自動でインストールされます。モデルは約1.6 GB で、初回のみダウンロードします）。代替は下記 |

ffmpeg がなくても画像と PDF は扱えます。音声認識エンジンがなくても、動画のキーフレームは得られます。

Claude は、プラグインの `skills/media-digest/scripts` フォルダから `digest.py FILE... --out OUTDIR` を実行します。主なオプションは `--lang zh`（音声の言語。既定は自動判定）、`--max-frames 24`、`--no-asr`（フレームのみ）、`--force`（やり直し）です。出力は `OUTDIR/digest.md` と `digest.json` です。結果はキャッシュされ、文字起こしがなかったファイルは、エンジンがインストールされると自動で再試行されます。

## 一斉送信・ライブアーカイブ・通知

- **複数のチャットへ1通送る。** 例：「このお知らせをリストの全員に送って」。Claude はリストを作り、まず**ドライラン**（すべての名前を解決するだけで、何も送りません）を行い、全宛先と正確な本文を見せます。名前が完全一致するか完全なIDの場合だけ有効で、部分一致や同名が複数ある場合はあなたに確認し、推測はしません。LINE の名前検索を完全に確認できないときは、完全なチャットIDを Claude が求めます。あなたの明確な「はい」の後に、数秒の間隔をあけて1件ずつ送ります。最初の失敗で止まり、再試行はせず、誰に届いたか・誰が失敗したか・誰にまだ送っていないかを伝えます。失敗した一斉送信は自動では繰り返しません（すでに届いた人に二重に届くため）。残りの人への送信は、あなたが望んだときだけ Claude が提案します。多数のチャットへ一度に送るとアカウントが制限される恐れがあるので、リストは短くしてください。
- **ライブアーカイブ。** `watch.py` はバックグラウンドでアーカイブを最新に保ちます。新着メッセージを待ち受け、届いた時点で保存し（添付ファイルは数秒後）、LINE が取りこぼしを知らせたら同期で追い付き、接続が切れたら自動で再起動します（短時間の失敗が10回続くと諦めるので、クラッシュの無限ループにはなりません）。`line watch` は同時に1つしか動かせないため、別のものが動いていれば `watch.py` はそう伝えて終了します。Ctrl-C できれいに停止します。Windows では `pythonw` で実行するか、タスクスケジューラでログオン時に起動します。コマンドはスキルの `references/watch.md` にあり、Claude はあなたに示すだけで、タスクを自分で作ることはしません。既定でアーカイブされるのは、すでにアーカイブフォルダがあるチャット、または `[watch] archive_chats` に書いた（あるいは `--archive` で指定した）チャットだけです。それ以外のチャット（一度も同期していない個人チャットなど）のメッセージは無視され、保存もログ出力もされません。`--archive-all` はすべてを保存するため、既定ではオフで、あなたが明示したときだけ使います。通常のテキストメッセージは LINE に問い合わせずに保存されるため、あなたの送信には影響しません。`watch.py` が完全な同期を行っている間（起動時、再同期、添付ファイルや不明な名前の取得）だけ、送信が「another line command is using the session」で拒否されることがあります。その場合メッセージは**送られていません**。少し待ち、あなたが確認してから Claude が送り直します。
- **欠落（gap）。** LINE が返すのは最新の100件だけで、このクライアントはさかのぼれません。そのため2回の同期の間に100件を超えて届くと、その間の分は二度と取得できません。同期はその時間範囲（`gap`）を知らせるようになりました。回避するには、より頻繁に同期するか `watch.py` を動かします。常駐プロセスを使いたくない場合の代替：Windows のタスクスケジューラで 15 分ごとに `sync.py --all` を実行します（`schtasks` コマンドは `references/watch.md`）。
- **VIP通知。** `config.toml` の `[watch] vip_chats` に重要なチャット（名前または完全なチャットID）を書くか、`watch.py` に `--vip` を付けます。実行中、そのチャットに新着メッセージが届くと、チャット名・送信者・短いプレビューを含む Windows 通知が表示されます（他のOSや通知の失敗時は、チャットと送信者だけを含み本文を含まないログ1行になります）。自分が送ったメッセージや古い溜まりは通知されません。アーカイブされていないVIPチャットも通知されますが、ディスクには何も書き込まれません。プレビューにはチャットの文面が画面に表示されます。

## 設定

設定しなくても動作します。任意の `config.toml` が2つあります（各スキルの詳細は `references/` に記載）。秘密情報は保存されず、環境変数の**名前**のみを記録します。

**`line-cli`**（Windows では `%APPDATA%\line-skill\config.toml`、それ以外では `~/.config/line-skill/config.toml`）：

| キー | 意味 |
| --- | --- |
| `line_path` | 特定の `line` プログラムを使用します（フォークや固定ビルドなど） |
| `archive_root` | アーカイブの保存先（環境変数 `LINE_SKILL_ARCHIVE` でも指定でき、そちらが優先されます）。既定：`%LOCALAPPDATA%\line-skill\archive`（Windows）、`~/Library/Application Support/line-skill/archive`（macOS）、`~/.local/share/line-skill/archive`（Linux） |
| `download.types`, `download.max_bytes` | 自動でダウンロードする添付の種類（`image`、`video`、`audio`、`file`）と、サイズ上限（バイト数。既定は20 MiB で、本クライアントが取得できる上限でもあります）、`download.line_emoji`（既定は `true`。LINE 絵文字リアクションの画像を1種類につき1回だけ保存） |
| `render.quiet_gap_days` | `messages.md` で、隣り合う2件のメッセージがこの日数より離れているとき「no messages for X days」の行を挿入します（既定 3。`0` で無効） |
| `watch.vip_chats` | 新着があると `watch.py` が通知を出すチャット（名前または完全なID）。例：`["Alice", "Project Team"]` |
| `watch.archive_chats` | すでにアーカイブフォルダがあるチャットに加えて `watch.py` がアーカイブしてよいチャット（名前または完全なID）。それ以外のチャットは無視されます |

**`media-digest`**（Windows では `%APPDATA%\media-digest\config.toml`、それ以外では `~/.config/media-digest/config.toml`。`MEDIA_DIGEST_CONFIG` で変更できます）：

```toml
[asr]
order = ["faster_whisper", "whisper_cpp", "groq"]   # try these in order

[asr.routes]                                          # per speech language
zh = ["faster_whisper", "groq"]

[adapters.groq]                                       # a cloud service, used because it is listed above
preset = "groq"                                       # api_key_env = "GROQ_API_KEY" comes with the preset
```

- エンジン：`faster_whisper`（ローカル、既定）、`whisper_cpp`（ローカル、`model_path` が必要）、`openai_compat`（OpenAI、Groq、vLLM、Speaches のプリセット、または独自の URL）、`command`（お持ちの任意のプログラム。独自のサーバーを含みます）。
- 設定ファイルがない場合、チェーンはローカルのみです。クラウドエンジンは `order` または `routes` に記載されている場合にのみ使われます。
- API キーは Claude Code を起動するシェルで設定してください（例：`export GROQ_API_KEY=...`）。キーをチャットに貼り付けないでください。
- 言語ごとのルートは、言語を指定した場合（`--lang zh`）に適用されます。`auto` の場合は適用されません。
- 完全なリファレンスは、`media-digest` プラグインの `references/config.md`、`references/adapters.md`、`references/install.md` にあります。

## プライバシー

- トーク、ダウンロードした添付ファイル、ダイジェストは非公開の会話です。お使いのマシンに保存され、プラグインのディレクトリには置かれません。絶対にコミット・公開せず、どの git リポジトリにも入れないでください。
- アーカイブは、お使いの PC 上にある非公開の会話のフォルダです（既定ではユーザープロファイル内で、プラグインのディレクトリには置きません）。保存先が git リポジトリ内にある場合は Claude が警告します。場所を移し、コミットや公開は絶対にしないでください。
- Claude はトークの内容を他のサービスに送信しません。文字起こしは、クラウドエンジンを設定しない限りローカルで行われます。クラウドエンジンを使う場合、Claude は音声を受け取るサービスを伝え、最初のアップロードの前に確認します。
- Claude がチャットで LINE のパスワードを尋ねることはなく、保存されたセッションを読むこともありません。
- 送信、リアクション、送信取消には必ず明示的な「はい」が必要です。バックグラウンドで送信されることはありません。
- 読んだメッセージには、AI に向けた指示が含まれている場合があります。Claude はそれを命令ではなく、単なるテキストとして扱います。

## トラブルシューティング

Claude に「LINE のドクターを実行して」と依頼してください。プラグインの `skills/line-cli/scripts` フォルダから `setup.py --doctor` が実行され、Python、`line` プログラムとそのバージョン、ログイン状態、キーリング（Linux）、設定ファイル、アーカイブフォルダへの書き込み可否、更新の有無を確認して、各項目について平易な対処法を表示します。バグ報告に貼り付ける前に出力を確認してください。ローカルのパスやアカウント名が含まれる場合があります。

| 症状 | 対処 |
| --- | --- |
| "line not found" | Claude にガイド付きインストールを実行してもらうか、設定の `line_path` を確認してください |
| "not logged in" | Claude にログインを依頼してください。Chrome 拡張機能からもログアウトされることに注意してください |
| ログインウィンドウが開かなかった | ターミナルで `line login` をご自身で実行し、その後 Claude に再確認を依頼してください |
| Linux：キーリングがない、またはロックされている | Claude が表示するパッケージ（`libsecret-tools`、`gnome-keyring`）をインストールし、キーリングのロックを解除してください。サーバーの場合は `references/setup.md` のヘッドレスオプションを参照してください |
| "busy" | 別の `line` コマンドが実行中です。少し待ってください（読み取りは自動で再試行されます） |
| "LINE session was invalidated or replaced by another client" | 別のパソコン（または Chrome 版 LINE）が唯一のセッションを引き継ぎました。Claude が理由を説明し、ここで再ログインする前に確認します（ほかの端末がログアウトされるため） |
| フレームはあるが文字起こしがない | 使用可能な音声認識エンジンがありません。Claude に一覧の表示と設定を依頼してください |
| "needs ffmpeg" | ffmpeg をインストール（上記参照）してから、再度実行してください |
| クラウドサービスで長い録音の文字起こしが失敗する | 25 MB を超える音声はまだ分割できません。ローカルエンジンを使ってください |
| メッセージが送信されたか不明 | Claude がまずトークを確認します。あなたの「はい」なしに再送することはありません |
| Claude が「欠落」を知らせる | 前回の同期以降に100件を超えるメッセージが届いたため、抜けた分は取り戻せません。同期をこまめに行ってください |
| メッセージに "(possibly unsent)" と表示される | アーカイブ後に LINE の直近100件から消えたため、送信取消された可能性が高いです。保存済みの本文は残ります |
| 写真やファイルに "expired" や "over 20 MiB" と表示される | LINE 側にもう存在しないか、本クライアントの上限を超えているため、ダウンロードできません |
| アーカイブが git リポジトリ内にあるという警告 | `archive_root`（または `LINE_SKILL_ARCHIVE`）をリポジトリの外のフォルダに設定してください |
| トーク名の検索が "LINE request failed" で失敗する | 上流は非アクティブも含む全トークの名前を一括取得し、1件の失敗で全体が止まります。Claude はアクティブなトークから検索する方式に切り替えて知らせます。非アクティブなトークは名前では見つからないため、完全な ID を使ってください |
| グループのメッセージが名前でなく省略された ID で表示される | 友だちでないグループメンバーは連絡先として照会できません。同期ではトークのテキストから名前を読み取りキャッシュします。それでも名前が出ない場合、その人は直近100件で発言していません |
| 特定の相手への送信が毎回「LINE request failed」で失敗する | 既知の制限です。送信自体は動作しますが、その相手の Letter Sealing の鍵が古いバージョンのため LINE が拒否し（エラー 10051／86「e2ee or version mismatch」）、上流はバージョンを下げて再試行しません。メッセージは送信されておらず、Claude はその旨を伝え、再試行しません。LINE アプリから送ってください。そのトークの読み取りは問題ありません |
| `chats --search` やグループメンバー名の取得が「LINE request failed」で失敗する | 上流のバグです。同じバッチに削除済みアカウントや友だちでないメンバーがいると、LINE の連絡先取得がバッチ全体で失敗します。回避済みです（アクティブなトークのみ検索、名前はトーク本文から取得）。上の2行を参照してください |
| Git Bash で Windows のインストールが `tar` エラーになる | Git 同梱の GNU tar は `C:` パスを読めません。インストール時は Windows 標準の System32 を PATH の先頭に置くようになりました。手動で行う場合は PowerShell から実行してください |
| `line-cli`（または `media-digest`）スキルが 2 つ表示される、または 1 つが 2 回動く | 同じスキルを Claude Code プラグインと `npx skills add` の両方で入れています。どちらか一方に：`claude plugin uninstall line-cli@line-cli-skills` または `npx skills remove line-cli` |
| Claude Code 以外：エージェントが `scripts/...py` を見つけられない、または `<SKILL_DIR>` と表示される | エージェントがスキルフォルダを補完していません。スキルの場所（グローバルは `~/.agents/skills/line-cli`、プロジェクト単位はプロジェクト内の `.agents/skills/line-cli`）を伝え、そこからスクリプトを実行させてください。リンクをたどれないエージェントは `npx skills add --copy timliudev/line-cli-skills` で入れ直します |
